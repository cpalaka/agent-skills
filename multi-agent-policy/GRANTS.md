# Hands-off execution grants

Read this when the owner wants a ticket, or a chain of them, executed with zero involvement —
merges, pushes, cleanup and Done included. A grant narrows the `implement-run` Skill: it converts a
ticket's gates, never skips them (2026-08-03).

- **Record the grant where the executing session will read it** — on the ticket, not only in chat.
  Name what is waived (sign-off and review items; merge, push and branch/worktree cleanup
  confirmations) and what stays in force: force-push, `--no-verify`, the verify gate, and
  `git-confirm-destructive`'s `gh` writes — narrowed to its gated set where the project imports
  `tracker-github`. One case still
  escalates: a foreign commit riding the push would publish someone else's work under the grant.
- **Backlog projects: commit the In Progress edit on the feature branch, not `main`.** Done lands on
  the branch (`git-flow-squash`), so an In Progress commit on `main` makes the squash-merge conflict
  on the task file every time: create the worktree, move the task inside it, commit there. Only a
  pin onto a dependent task (a different file) stays on `main`.
- **Convert every human-eye AC into a machine probe.** "Audio audibly stops" becomes the adapter
  receiving destroy and the element leaving the DOM. An AC only a human can check makes the ticket
  hands-on whatever the grant says. What the machine cannot self-certify batches into one
  deliberately human ticket at the chain's end.
- **Demote look-checks to non-gating committed artifacts** (screenshots, with paths recorded on the
  ticket) for async review — only when an upstream, approved design-reference ticket carries the
  frozen feel verdict. Visual work otherwise stays attended (`parallel-work`).
- **Make the close-out an explicit AC** (gate green, merge, push, cleanup, Done) so the autonomous
  finish is checkable rather than improvised.
